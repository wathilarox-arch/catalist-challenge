## 4. LLM layer: free DeepSeek via OpenRouter (read carefully)

I want to use a **free DeepSeek model through OpenRouter**. Facts (verified from OpenRouter docs, Nov 2026 — re-check at runtime, they change):

- Models with IDs ending in `:free` are limited to **20 requests/minute**.
- **50 requests/day** if all-time credits purchased are < $10; **1,000/day** if ≥ $10 (one-off top-up). `GET https://openrouter.ai/api/v1/key` reports `free_model_daily_requests` (used / limit / remaining).
- A 429 returns `error_type: "rate_limit_exceeded"` with `X-RateLimit-*` headers; `Retry-After` is present only sometimes. A limit hit mid-stream arrives as an SSE event with `finish_reason: "error"`, not an HTTP status.
- **I have NOT confirmed which DeepSeek `:free` model IDs exist right now**, or whether each supports tool calling / JSON mode. Free endpoints have no SLA and may be quantised.

Therefore:

1. **Model IDs come from env, not code.** `.env.example`:
   ```
   OPENROUTER_API_KEY=
   MODEL_EXTRACT=        # a non-reasoning chat model, e.g. a DeepSeek V3-class :free model
   MODEL_AGENT=          # may be the same; a reasoning model is optional here
   MODEL_FALLBACKS=      # comma-separated :free models to try on repeated failure
   LLM_RPM=15            # stay under 20
   LLM_CONCURRENCY=1
   DAILY_REQUEST_BUDGET= # defaults to the remaining quota from /api/v1/key
   ```
2. Write `scripts/models.ts` (`npm run models`): call `GET /api/v1/models`, list models whose id ends with `:free`, flag those containing `deepseek`, and print `context_length` and `supported_parameters` for each. I pick the IDs from that output. Do not guess IDs.
3. **Do not rely on native tool calling or `response_format`.** The agent loop is code-driven: the model returns a JSON object (an "action"), code validates it with zod and executes it. This works on any model and makes swapping models trivial.
4. `lib/llm/client.ts` must provide:
   - token-bucket limiter (default 15 RPM) + concurrency cap;
   - retry with exponential backoff + jitter, honouring `Retry-After`; treat 429, 5xx, empty content and mid-stream errors as retryable; after N failures move to the next fallback model;
   - **persistent response cache** in SQLite table `llm_cache` keyed by `sha256(model + messages + params)`, so ingest is **resumable** and re-runs are free (critical with a 50/day cap);
   - **call log** table `llm_calls` (ts, model, purpose, prompt_tokens, completion_tokens, latency_ms, cached, status) from the API's `usage` field, used for the cost report in §12;
   - **daily budget guard**: before each call, check the remaining quota; if exhausted, stop cleanly with a message saying how many calls remain pending, never loop;
   - strip `<think>…</think>` blocks from reasoning models;
   - `temperature` 0–0.2 for extraction/reconcile/agent steps.
5. `lib/llm/json.ts`: extract the first balanced JSON object from the text (handle code fences and prose), validate with zod, and on failure do **one repair retry** that sends the validation error back. Count repair rate in `llm_calls`; report it in the write-up.
6. **Plan the call budget up front.** Write `npm run plan:calls`, which prints estimated calls for ingest (≈ 1 extract call + 1 reconcile call per meeting; more if a meeting exceeds the model's context and must be windowed) against the remaining daily quota and RPM, and the number of days / minutes it will take. **Ingest in priority order**: the teams named in `questions.json` plus `TS3012` first, then the rest. Support `--teams` and `--limit`.
7. Be upfront with me in the plan: with < $10 credits the 50/day cap makes full ingestion take about a week; with the one-off $10 top-up it takes under an hour. Also warn that the public demo's live mode can exhaust the quota, so §9 requires guards and precomputed fallbacks.

## 6. Data model (SQLite)

```sql
CREATE TABLE meetings (
  meeting_id TEXT PRIMARY KEY,   -- 'TS3012b'
  team TEXT NOT NULL,            -- 'TS3012'
  seq INTEGER NOT NULL,          -- a=1,b=2,c=3,d=4
  n_turns INTEGER, n_words INTEGER
);
CREATE TABLE turns (
  turn_id TEXT PRIMARY KEY,      -- 'TS3012b:0042'
  meeting_id TEXT NOT NULL REFERENCES meetings(meeting_id),
  idx INTEGER NOT NULL,
  speaker TEXT NOT NULL,         -- 'A'..'D'
  start_sec INTEGER,
  text TEXT NOT NULL,            -- ORIGINAL, exact
  n_words INTEGER NOT NULL,
  citable INTEGER NOT NULL       -- n_words >= 6
);
CREATE VIRTUAL TABLE turns_fts USING fts5(text_clean, content='', tokenize='porter unicode61');
-- rowid of turns_fts == rowid of turns; text_clean is the normalised index copy

CREATE TABLE events (            -- raw LLM extraction output, per meeting
  event_id TEXT PRIMARY KEY, meeting_id TEXT, team TEXT,
  type TEXT,                     -- proposal|decision|rejection|objection|action_assigned|action_report|number|open_question|answer
  slot_hint TEXT, summary TEXT, speaker TEXT,
  turn_ids TEXT,                 -- JSON array of turn_id
  value_raw TEXT, refers_back INTEGER, refers_note TEXT
);

-- Append-only versions. Current state "as of meeting N" = latest version per item with meeting_seq <= N.
CREATE TABLE ledger (
  item_id TEXT, version INTEGER, team TEXT,
  kind TEXT,                     -- decision|action|disagreement|number|question
  slot TEXT,                     -- canonical topic: energy_source, case_material, display_lcd, speech_recognition, budget, target_group, navigation_control, find_my_remote, colour, shape, chip, ...
  value TEXT,
  status TEXT,                   -- proposed|agreed|rejected|superseded|open|done|dropped|resolved
  meeting_seq INTEGER,
  owner_speaker TEXT,            -- actions only
  evidence TEXT,                 -- JSON array of turn_id (must be in meeting_seq's meeting)
  supersedes TEXT,               -- item_id@version replaced by this version
  rationale TEXT,
  PRIMARY KEY (item_id, version)
);
CREATE TABLE llm_cache (key TEXT PRIMARY KEY, response TEXT, created_at TEXT);
CREATE TABLE llm_calls (id INTEGER PRIMARY KEY, ts TEXT, model TEXT, purpose TEXT,
  prompt_tokens INT, completion_tokens INT, latency_ms INT, cached INT, status TEXT);
```

## 7. Citations: the most important correctness mechanism

Build `lib/citations.ts` first, with tests, before any LLM code.

- **Normalise** for comparison: lowercase, collapse all whitespace to single spaces. **Do not strip punctuation or alter words** (`L_C_D_` stays `L_C_D_`).
- **Validator** (mirrors the grader): a citation is valid iff (a) `meeting_id` exists; (b) the normalised quote is a **contiguous substring of ONE turn's** normalised text; (c) the quote has **≥ 6 words**. A quote spanning two turns is invalid. Write unit tests for: valid, 5-word quote, cross-turn quote, case/spacing differences (valid), altered word (invalid).
- **Resolver**: the LLM returns evidence as `{meeting_id, turn_id, anchor}` where `anchor` is an optional 3–8-word phrase it believes is in that turn. Code locates the anchor (case-insensitive) and expands to a contiguous window of **6–30 words** inside that turn (prefer sentence boundaries), then outputs the **raw substring**. If the turn has < 6 words, or the anchor isn't found and no sensible window exists, reject with a machine-readable reason.
- **Retry loop**: on any rejection, feed the reasons back to the agent ("turn X is too short; choose another turn") for up to 2 retries. Final `answers.json` generation **must** run every citation through the validator and fail loudly if any is invalid. Report the citation-valid rate.

## 8. Pipeline

### 8.1 Parse (code)
`lib/parse.ts`: read each file, parse header + turns (tolerant of odd whitespace), assign `turn_id = meetingId:idx` (zero-padded), compute `n_words`, `citable`, and a cleaned index copy (lowercase, filler words like um/uh removed, spelled-out acronyms indexed in both forms, e.g. `L_C_D_` is indexed as both `l_c_d_` and `lcd`). Tests: counts match (138 meetings, 48,148 turns), incomplete teams handled, no turn lost.

### 8.2 Spoken numbers (code)
`lib/numbers.ts`: `parseSpokenNumbers(text) → {value, raw, unit?}[]` handling at least: "twelve and a half Euros" → 12.5; "twelve fifty" (in a money context) → 12.50; "fifteen Euros" → 15; "two point five" → 2.5; "a hundred and fifty" → 150; digits as-is. Ambiguity is flagged, not guessed (`confidence: 'low'`). Sums use code, never the LLM. Full test table.

### 8.3 Extract (LLM, once per meeting, resumable)
Render the meeting as `[idx] Speaker X: text` (you may drop pure-backchannel turns < 3 words from the prompt but keep original idx numbers). If it exceeds ~70% of the chosen model's context window, split into overlapping windows and dedupe events by (type, slot_hint, turn overlap). Output validated by zod:

```json
{"events":[{"type":"decision","slot_hint":"energy_source","summary":"≤25 words","speaker":"B",
  "turn_idxs":[212,213],"value":"solar cell + dynamo","refers_back":true,
  "refers_note":"'the thing we said last time' = case material choice"}]}
```

Prompt rules: only extract what is actually said; every event must cite turn idxs it is based on; mark `refers_back` when a speaker alludes to an earlier point without naming it; prefer the seed slot vocabulary but allow `other:<short label>`; never invent values; numbers stay as spoken strings (`value_raw`), parsing is done later by code. Code then verifies every `turn_idx` exists and drops events with invalid evidence.

### 8.4 Reconcile (LLM, once per meeting, sequential per team)
Input: the team's ledger **as of the previous meeting** (compact list: item_id, kind, slot, value, status) + this meeting's events. Output ops, zod-validated:

```json
{"ops":[{"op":"supersede","target":"item_12","kind":"decision","slot":"case_material",
  "value":"rubber","status":"agreed","evidence_turn_idxs":[88],"rationale":"…"}]}
```
Ops: `new`, `confirm`, `supersede`, `reject`, `open_disagreement`, `resolve_disagreement`, `close_action`, `drop_action`. This step is also where vague back-references get resolved against existing ledger items.
Code applies the ops by **appending** ledger versions (never mutating), sets `meeting_seq`, links `supersedes`, canonicalises slots (synonym map in code), and rejects ops whose `target` doesn't exist or whose evidence isn't in the current meeting.
Teams are independent → process teams in parallel (subject to the rate limiter); meetings **within** a team strictly in order.
Why this scales: the reconcile prompt holds one team's ledger (a few thousand tokens), never the corpus. New meeting = one extract + one reconcile call.

### 8.5 Retrieve (code)
`Retriever` interface: `search(team, query, {maxSeq?, meetingId?, k}) → TurnHit[]`. FTS5 implementation: always filter by team; build an OR query with prefix matching from LLM-supplied keywords; BM25 rank; prefer `citable` turns when ranking ties; return each hit with ±1 neighbour turns for context. Hard filter on `maxSeq` so as-of queries can't leak later meetings.

## 9. Question-answering agent (`lib/agent.ts`) + UI

Loop (max **6** LLM steps per question):

1. **Code**: detect team from the question text or `question.team`; load the team's ledger (current + history) as a compact timeline.
2. **LLM planner** returns one JSON action per step (validated with zod):
   - `{"action":"search","query":"keyword keyword …","meeting_seq":null|1..4}`
   - `{"action":"read","meeting_id":"…","from_idx":N,"to_idx":M}` (max 40 turns)
   - `{"action":"numbers","meeting_id":"…"}` → code returns turns containing parsed numbers
   - `{"action":"final","answer":"1–3 sentences","evidence":[{"meeting_id","turn_id","anchor"}]}`
3. **Code** executes the action and appends the result to the scratchpad; repeat.
4. On `final`: resolve citations (§7); if rejected, retry as described; else emit.
- Answer style: 1–3 plain sentences; give speaker letter (and role if clear); state final state *and* what changed (what it was before, what replaced it, why) for time-based questions.
- Log every step (action, hits, tokens) so the UI and write-up can show the trace.

**Next.js UI** (build last, ≤ 1–2 hours):
- `/` Ask page: question box, streamed agent steps (SSE), final answer, **expandable citation cards** showing the cited turn with the quote highlighted and neighbour turns.
- `/team/[id]` **Timeline**: each topic slot as a chain across meetings a→d, current value marked, superseded values struck through, each node linking to its evidence turn. (This is the clearest demo of "knows what is current".)
- `/brief/TS3012` shows the brief with citations.
- `/api/ask`: `runtime='nodejs'`, `maxDuration=300`, streams steps. **Guards:** per-IP rate limit, per-session question cap, in-memory LRU answer cache, daily-budget check; when the free quota is exhausted, switch the UI to "precomputed mode" that serves `answers.json` and the team timelines and says so plainly.
